# myMoney MVP 鎖定方案

## 核心判斷

採用**單一 Nuxt 靜態 SPA**。沒有 Express、常駐 API 或本機資料庫行程。

- IndexedDB：日常自動保存與最近 3 份內部版本
- JSON：完整備份／復原與跨裝置搬移
- Excel：只匯出資產盤點歷史，不作復原格式

## 儲存策略

1. 所有操作一律先保存到目前網址的 IndexedDB，不依賴本機檔案權限。
2. 每次實際資料編輯前把上一版放入 IndexedDB，最多保留 3 份。
3. JSON 是使用者主動建立的完整備份，每次另存獨立檔案，不長期連結或自動同步。
4. 保存最近一次 JSON 的檔名、時間與資料版本，用來提示是否有尚未備份的實際變更。
5. JSON 復原前先顯示帳戶、持倉、收支與盤點摘要，確認前保留目前 IndexedDB 版本；匯入會做欄位 allowlist、危險鍵過濾、檔案大小與集合筆數上限。
6. 自動市場資料、匯率與自動股價仍寫入目前資料，但不會單獨觸發「尚未備份」狀態。
7. 儲存邏輯集中在 `app/services/`；未來若線上化，以新增 Remote Storage Adapter 為原則，避免重寫頁面與領域計算。
8. 外部連結（Yahoo）一律由商品代號重算；Store 寫入以佇列互斥避免並行覆蓋。

## MVP 範圍

### 帳戶與資產

- 自由新增、重新命名、排序、編輯與刪除兩層帳戶結構；刪除前必須再次確認。
- 流動性只影響「可立即動用」統計：立即可用會計入，可變現與受限制不計入；不影響已納入資產的總資產與淨資產。
- 群組可永久刪除；刪除前需二次確認，並明確列出群組內項目與驗算草稿會一起移除。
- 現金、股票、債券、其他資產與負債分類。
- TWD、USD、JPY 三種幣別；USD、JPY 以每日參考匯率換算並獨立統計為外幣資產。
- 立即可用、可變現、受限制三種流動性。

### 投資與現金

- 投資持倉保存代號、數量、類別、方向與價格；可手動排序並保存順序。
- 台股最新收盤價優先使用 FinMind 公開日行情 API，證交所／櫃買中心商品快取僅作為失敗備援；介面提供 Yahoo 股市核對連結。
- 現金驗算可依設定開關：啟用時依帳戶保留驗算草稿並更新系統現金；關閉時改由帳戶結構直接管理金額。

### 週期收支

- 可建立收入／支出項目，支援每月、每季、每半年、每年。
- 顯示指定月份實際會發生的金額，以及換算後的月均與年總額。
- 選取試算以「排除選取後」呈現收入／支出／淨額的目前 → 排除後對照。

### 盤點與總覽

- 每日一筆盤點快照；同日再次保存會更新原紀錄。
- 盤點頁自動彙整帳戶與持倉，不提供第二個資產編輯入口；需填加權指數與 240MA。
- 總覽顯示淨資產摘要、部位加權與曝險比例、三組折線圖（淨資產趨勢、標準化對照、大盤與 240MA），以及依年份分頁、區塊內捲動的盤點與大盤紀錄。
- 加權指數與 240MA 使用相同的證交所每日資料；240MA 為最近 240 個交易日收盤指數的算術平均。
- 金額、數量、價格與市場點數的輸入及顯示使用千分位，實際保存仍為數值。
- JSON 匯出／匯入交換完整資料；Excel 只匯出資產盤點歷史。

## 非目標

- 登入、多使用者、銀行與券商串接。
- 交易成本、損益、股利與盤中報價。
- 目標配置比例與「應投入／應保留」差額試算（已自產品移除）。
- 讓靜態網站無權限存取任意本機路徑。
- 本機 Express／常駐 API server。

## 主要風險

- 網址或 Port 改變：設定頁顯示目前 origin，提醒不同來源會使用不同 IndexedDB。
- JSON 儲存取消或失敗：不顯示為資料保存失敗，IndexedDB 內容維持不變。
- 瀏覽器不支援原生另存視窗：改用一般 JSON 下載。
- TWSE／TPEx／FinMind 跨來源請求失敗：名稱與收盤價改用建置時保存的官方資料快取，海外或未收錄商品才改用手動輸入。

## 完成條件

- `npm run build` 可產生可獨立部署的 `.output/public`。
- 純靜態部署即可運作；不依賴本機 API port 或 Express。
- 可建立附日期時間的 JSON、預覽後復原，並判斷目前資料是否比最近一次備份更新。
- 重新整理後資料仍存在相同網址與 Port 的 IndexedDB。
- 同日快照更新、資產計算、週期收支與市場／匯率相關測試通過。
